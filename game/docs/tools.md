# Tools

The `npm run` commands and debug tools. Run them from `game/`. What each bot archetype does is in [Bots](architecture/bots.md).

## Browser checks

These commands drive headless Chromium. All but `boot:time` and `perf` need the dev server. Screenshots go to `.playtest/`. A GPU run fails when Chromium falls back to software drawing. The GPU is Metal on a Mac and Vulkan on Linux.

- `npm run playtest [-- --url <url>] [--turns <n>] [--cpu] [--no-fps-gate]` boots the game, plays turns and fails on page errors, the crash screen, a missing or zero-size canvas, a run that ends short, a dead corner on a HUD panel made of one control, a frame rate under 50 and any language control outside the Options panel. It also switches the language to Russian by keyboard and back to English by mouse. Its browsers emulate the WebGL 2 floor of 16 fragment texture units, so a program over it fails to link as on a small GPU. At night, with 6 lit trucks and the player's lamps on, it checks that every program links and that the ground is drawn: it renders one frame over a magenta background and fails when magenta shows around the truck. Roaming plays this in the main browser through 3 night turns and a reload, and Chaos Highway in a second, software browser at the night peak and after a reload, since the highway crashes headless Chromium on Vulkan on the factory host. The software browser adds about 5 minutes, and `--cpu` skips the Roaming night turns, since software drawing stretches each turn to minutes. It writes `.playtest/night-roaming.png` and `.playtest/night-highway.png`. `--turns` defaults to 12 with 10 seconds per turn. `--no-fps-gate` only prints the FPS. `--cpu` draws in software, skips the FPS check, plays 4 turns with 60 seconds per turn and is for machines without a GPU.
- `npm run ui-playtest` checks the HUD layout at several viewport sizes, from the readouts and the event log to the radio, the weapons dock and modal frames, and that the bottom-left outline (`.bottom-left`, `.instruments`, `.weapons` and the foot of the truck stack) stays within 1px through every switch, weather and value state (`scripts/hud-outline.mjs`). It needs the dev server at `http://localhost:5173`. `CPU=1` drops the GPU flags and allows 180 seconds per step. `DOCK_ONLY=1` checks the weapons dock only.
- `npm run boot:check [-- --url <url>] [--cpu] [--only <case>]` checks the boot screen at 1280x800 and 390x844 for a fresh game, a saved game, the save rescue screen, the start menu, a failed map, a map that never arrives (Try again), one dropped map request, a failed game module, a dropped and a lost model, and a dropped and a lost turn worker script. `--only startMenu` runs one case. `--browser firefox` runs the same cases in Firefox and names its screenshots `.playtest/boot-firefox-*.png`. Firefox takes no GPU flags and opens a window, since headless Firefox gets no WebGL. On Linux without a display, run it under `xvfb-run -a`. Screenshots go to `.playtest/boot-*.png`.
- `npm run mobile -- [--url ...] [--cpu] [--only portrait|landscape|phone|size|tap] [--ui-size <percent>] [--fast]` plays the loop by touch on a 390×844 and an 844×390 phone in Chromium touch emulation (`hasTouch`, `isMobile`, device scale factor 2): a new game from the start menu, a map drag, a pinch, a ground tap, a ground hold, End turn, a truck tap and its second tap, the card's close button, a town tap, a purchase, the inventory with a held drag, then a one-finger select, preview, Rotate and place, the Driver screen, a tap on a part of the pinned card, every drawer, Menu, Help and Options, a long press on a disabled control, a save, and a reload with Continue. Landscape continues that save, repeats the main steps and turns to portrait mid-game. It drives the game with real touches only (`page.touchscreen.tap` and CDP `Input.dispatchTouchEvent`) and reads the result from `window.__ROAM__`. After every step it saves `tmp/mobile/<orientation>-<nn>-<step>.png` and runs `findLayoutFaults` and `findMobileFaults` from `src/ui/dom.ts`: clipped text, overlap, an unreachable or covered primary control, sideways overflow, a visible control under 32px, a key cap such as [C] in a visible label or title, a page error and the crash screen. Before the journey it plants a transparent cover over the canvas and a 600px wide element and a `[Q]` label, and throws unless all of them, and a tap through the cover, are caught. It prints PASS or FAIL per step and ends with "touch emulation in Chromium, not a real device". It needs the dev server. `--fast` hides the 3D view and draws at scale 1, for fixing a layout. The `phone` run repeats the landscape steps on a 798×375 phone at 80% UI size. The `size` run picks 90% in Options by touch on that phone, taps an off step for its reason, and checks that the pick survives a reload. `--ui-size` stores that UI size for the portrait and landscape runs. The `tap` run boots a new game and checks only that a tap at the drawn screen point of a ground point sets the order within 0.3 tiles of it, also with `#game` 56px shorter than the window and after hiding and showing `#game`. It takes about 4 minutes per orientation with `--cpu`.
- `npm run sounds:decode-check -- [--url http://localhost:4173/] [--break <file,file>|all] [--cpu]` serves 0xFF bytes for the named sound files in a production build and passes when the boot reaches `roam:ready`, shows no crash screen or page error, and the page holds exactly one `Sounds failed to decode: N of 104` line. Run it against `npm run build && npx vite preview`. On a build from before hotfix #482 it fails with a crash screen.
- `npm run boot:time [-- --url http://localhost:4173/] [--runs 5] [--viewport wide|narrow] [--net none|4g]` times boot on the GPU. It runs a fresh game on a cold cache, then a saved world on a warm cache. It prints the median and max of `roam:ready`, each boot step and the code, map, model and sound fetch spans. `--net 4g` throttles to 10 Mbit/s with 40 ms latency. It only measures. For production numbers run it against `npm run build && npx vite preview` and compare runs only on the same host.
- `npm run perf -- --url <dev server> [--seams-only]` times boot, turns, move previews, frames over the towns by day and at night, and automatic travel. It first plays 8 turns of a fresh game at seed 1337 and prints a seam report with no budget. `--seams-only` stops after the report. It fails on a miss against `scripts/perf-budgets.json`.
- `npm run layout [-- --cpu]` boots a new game on a fixed seed and checks the surveyed screens in English, Russian and pseudo-long text at 1280x720 and 700x800, and the inspector also at 1440x900. It fails on clipped text, text out of its box, sideways page scroll, overlapping or unreachable controls, missing Cyrillic glyphs, English in Russian a quest page picture frame outside its shape (`quest-frame-shape`) and a checker that misses its planted overflowing button. After the language passes, an English pass checks the HUD, the inventory, the shop and Options at 1280x720 with UI size 130% and 80%, and at 640x360 at 100%, the smallest layer, and writes `tmp/layout/<screen>-en-<w>x<h>-ui<percent>.png`. An empty `LAYOUT_LOCALES=` runs only that pass. It writes `tmp/layout/<screen>-<language>-<w>x<h>.png` and `tmp/layout/faults.json`. `LAYOUT_LOCALES=ru` and `LAYOUT_STATES=shop,trade` narrow a run. [Text and languages](architecture/text.md#the-layout-check) has the details.
- `npm run site:shot -- <site-id>[,<site-id>] [--hour 23[,12]] [--zoom 1] [--out .playtest/sites] [--url http://localhost:5173]` moves the truck to each site's first pad, sets the hour and saves one screenshot per site and hour. It fails on any browser error.
- `npm run shot -- [<scene.shot.ts>] [--model <name>[,<name>]] [--truck <chassis> --hp 100,50,0] [--camera quarter|game|front|back|top|left|right|bottom|all] [--zoom 1] [--hour 12] [--out tmp/shots] [--cpu]` draws assets into one labeled PNG sheet and prints its path. It needs no dev server and opens no window. It draws through the game's own models, materials, sun, sky and model fill, with no outline pass and no terrain. `--model` draws one row of models from `NAMES`. `--truck` draws the truck on that chassis from a new world, the player's truck first, at each HP share on every mounted part. When no truck in the new world drives that chassis, it draws the gear the first driver who rolls the chassis would carry, or the bare chassis when no driver rolls it, like the semi. A scene file draws anything else: it default-exports a `Shot` from `src/three/shot.ts`, with rows of panels, each a label and a `build()` that returns a Three.js object. The kit has `model()`, `vehicleOn()`, `withHp()`, `truck()` and `world()` for scene files to use. Every view frames all panels at one shared scale. `quarter`, the default, looks from the game's camera direction. `front`, `back`, `left` and `right` look level at that side of a truck facing +x, and `top` and `bottom` look straight down and up with the nose at the top. `all` gives each panel its own row with the 3/4, front, back, top down, left side, right side and bottom views. `game` draws at the game's own scale for a 1000 px tall window at that `--zoom`, so a detail shows at the size a player sees it. `--hour` lights the sheet with the game's daylight at that hour. It fails on any page error, an unknown model or chassis and an empty panel.
- `node scripts/garage-ui-check.mjs <url>` checks the garage: selection, the shop comparison, header and repair bar labels, truck cards on the Trucks tab, and the layout from 800 to 1920 wide.
- `node scripts/shop-parts-check.mjs <url>` checks the compact shop part rows: collapsed by default, one open at a time, keyboard, purchase, filter and narrow layouts.
- `scripts/gpu.mjs` holds the GPU flags for the playtest, perf, icons and UI playtest scripts.

## Tests

- `TEST_TIMEOUTS=off` removes every clock time limit from `npm test` and `npm run playtest`. The factory sets it on its shared server, where a slow test is load, not a hang, and the full suite on GitHub Actions sets it too. There the stall watch stops a hung run.
- `TEST_STALL_MINUTES` sets the stall watch. `test:cached` stops a run in which no test finished for that long, and `npm run playtest` fails when it prints nothing for that long and names the last line it printed. The factory checks set it from `FACTORY_TEST_STALL_MINUTES`, so a hung playtest fails as a hang instead of running into the checks time limit.
- Every Vitest run limits CPU time, with `TEST_TIMEOUTS=off` too. A test may use 30 s of CPU time and a test file 90 s on the reference runner, imports and hooks included. `src/test/cpu-limits.ts` holds the limits, and no test can raise them. A GitHub runner on an AMD EPYC 7763 uses about 2.2 times the CPU time of a fast laptop for the same test, so a fast laptop gets limits of about 13 s and 40 s. The suite runs two workers per four-CPU runner, since four workers inflate each test's CPU time about twofold.

The limits scale with machine speed, so the same file gets the same verdict on every runner model and on the machine where it was written. Global setup times the empty test world build 3 times, takes the median CPU time, prints `[cpu-limits] runner speed workload <ms> ms, limits scaled by <factor>` and hands the factor to every worker. The limit is the base limit times the factor, with the factor being the workload time divided by `REFERENCE_WORKLOAD_MS` in `src/test/cpu-limits.ts`, the workload time on an AMD EPYC 7763. A 7763 gets about 30 s and 90 s, and a faster runner gets tighter limits. Samples from GitHub runners: 7763 about 1400 to 1570 ms, Intel Xeon 8573C about 1310 to 1380 ms, 9V74 about 1030 to 1060 ms and 9V45 about 760 to 860 ms. The 7763 spread is about 12 percent from lowest to highest.

A test over a limit fails, and the message names the factor. Make it cheaper without cutting coverage: keep every case, seed and turn, build shared worlds once and clone them, and split cases into their own tests or files.
- `TEST_SUITE_MINUTES` stops a `test:cached` run that runs longer and prints its slowest finished files. It exits 3 when no test file failed by then and 1 when one did. The full suite on GitHub Actions runs in eight shards of every eighth test file, sets 35 per shard and counts exit 3 as a machine failure.
- `TEST_FAILURES_FILE=<path>` makes `test:cached` write `{"failed": [{"file", "test"}], "unhandledErrors", "unfinished": ["file"]}` there when the run ends: each failed test by file and full name, with `test` null for a file that failed outside its tests, and every selected test file that did not finish. A run that stalls or runs past its limit writes the record too, with the failures seen so far and the unfinished files; a normal run writes `"unfinished": []`. It deletes the file first. Worker RPC timeouts on `onTaskUpdate` do not count as unhandled errors. The full suite on GitHub Actions uploads it, and the factory reads it to tell a failure that the base also has from a new one.
- `TEST_WORKERS=<n>` sets how many workers Vitest runs at once. The default is one per CPU, up to 6. The value must be a whole number of 1 or more.
- The full suite keeps its run time down by sharing setup between tests. A Vitest global setup builds the empty test world once per run and `emptyWorld()` copies it. Tests that need a full start world call `standardWorld(seed)` or `reusedWorld(key, build)` from `src/test/world-cache.ts`, which build it once per file and hand out copies. Copy worlds with `cloneWorld`, never `structuredClone`, so a frozen terrain stays shared and its nav layers are not rebuilt each turn. `editableTerrain()` returns a frozen terrain object whose `heights` and `types` arrays a test can still edit in place.
- The runner in `src/test/settled-runner.ts` waits for Vitest's pending status replies before each hook and each test. A synchronous stretch over 60 s that starts while a reply is pending times out Vitest's worker RPC, even when the reply came back at once.
- `npm run test:cached -- --cache <dir> [test files]` is in [CLAUDE.md](../CLAUDE.md).

## Progression bots

The recorder plays bots through the real turn pipeline, headless. [Bots](architecture/bots.md) describes the archetypes. Run long batches in the background with a log, and mine a batch fully before you rerun anything.

- `npm run progression:record -- --archetypes trader,scavenger,hunter,fastTrader --seeds 1,2,3 --turns 2000` plays one bot per archetype and seed, one at a time, and writes the traces to `tmp/progression/`.
- `--out <dir>` sets the trace directory.
- `--kit <id>` starts every run from that start kit instead of the archetype default.
- `--markov-turns <k>` is the turns the `markov` archetype keeps one goal. It is required with `markov`.
- `--settings damage=2,fuelUse=1.5` starts every run with those [world settings](wiki/mechanics/world-settings.md). A bad value fails the run.
- `--physics true` moves the trucks near the player by the game's physics, as the browser does, so rams, crashes, hazard scenes and close fights play out. The default uses the cheap far rules for every truck. Use it for the `escort`, where fights decide the run.
- `--tolerate-stalls true` keeps a run going after a stall.
- `--patch <file>` imports a module before the run. See the A/B test below.
- A run that hits an error ends with an error line, the next run starts, and the batch fails at the end. A recorder run throws when a stall happens, when most NPCs are dry at once in a world with traffic, or when money changes by more than the money events explain.
- The Roaming archetypes play a Roaming world. The `escort` and the `sprinter` play Chaos Highway.
- `npm run stuck` records a trader for seeds 1 and 2 and 500 turns, and fails on any error, stall or dry majority. It prints the stall with the driver's goals, order, route and neighbors. Run it after a change to NPC goals, services or tows.
- `npm run progression:report [-- <dir> [<dir>]]` replays every trace in `tmp/progression/` or in the given directory with the current XP rules. It prints, per archetype, each activity family's XP per day and the pooled XP per day, the days the pooled XP covers each rank in one skill and in every skill against the targets in `src/data/skills.ts`, the wage per turn at each gear tier, fights won, knockouts, gear lost, deaths, net worth by day and money by ledger key. A last summary has one line per bot with profit per turn, net worth gained per turn and the ratio to the trader. Net worth counts truck damage at its repair bill and ignores goods a haul contract carries. Profit is every ledger key but gear. Two directories give each bot's summary on side A and side B and the change in money per day by ledger key.
- `npm run progression:watch -- --archetype trader --seed 1 --to 5000 [--from 4500] [--markov-turns <k>]` plays one run and prints the player truck turn by turn: money, net worth, goods, contracts, order, part HP and the events that touch the player.
- `npm run progression:analyze -- <dir> [--run <bot>-<seed>]` sweeps a batch for trouble: time in combat, stranded or towed, each fight with its odds and outcome, standoffs, big losses, tows, stalls, debt, dry tanks, flapping rules, the population per faction, where raiders are relative to roads, the raiders' `preyPassed` reasons, lost trucks and NPC solvency by role. `--run` narrows it to one run.
- `npm run progression:playthrough -- --seed <n> --turns <n> --out <file> [--archetype markov] [--every 50] [--sha <sha>]` plays one run and writes its activity log: every game event, a snapshot of the player and every NPC every `--every` turns, how the run ended and a summary. The factory's release playtest reads the log. The log goes to a `.part` file that is renamed when the run ends. A bad argument exits 1. An in-game error or stall ends the log with an error line and exits 0.
- Simulation mode is the harness in a browser: `npm run sim` starts the dev server and opens `/sim.html`, which resumes the saved run or starts one on a random seed. `/sim.html?seed=<n>` starts a new run on that seed. A worker plays the markov bot's run of `progression:playthrough`: the same start world from `playthroughWorld()` and the same `PLAYTHROUGH_OPTIONS` in `src/sim/progression/activity.ts`, plus tolerated stalls, so a stall shows in the log instead of ending the run. Same seed, same game: a test checks that the whole world after 10 turns equals the playthrough's. Do not add a rule or a shortcut that only the sim uses. A speedup goes into the harness, so both get it. The worker saves the run in the game's save format to its own database, `saveKey('sim')`, every game hour and on Pause, with the run's ledger and its history. The history has one sample per game hour: money, worth, XP, the stock and buying price of every good at every town, and the site and road events of that hour. A save whose samples lack any of these, or hold the market in another layout, is from an older sim mode, so the worker deletes it and starts a new run. Download save writes the same file. The page draws every truck on the 2D map by faction, with pan, zoom, a speed choice and a camera that can follow a truck. W, A, S, D and the arrow keys pan the map at 600 screen pixels a second while held, at any zoom, and stop Follow like a drag does. Text boxes ignore them. The side column holds the run toolbar, then your truck's panel, which charts money and net worth on one axis and XP on its own, one sample per game hour, with the values under the cursor. Heat, on the map, shades where raiders, traffic or fights spent their turns since the page opened, so raider ground can be held against the traffic it hunts. The log keeps the last game day of events, newest first, in the game's own words where it has them and in plain sim words otherwise. Routine NPC events, such as jobs, trades and shots, show only with All events on or when they name your truck. A time prints once per group, lines that name your truck carry the player's edge, and Find filters by text. A click on a marker or a log line opens the truck's card, which shows its key numbers, true flags as tags, places as map squares, parts grouped by kind with the weakest first, and on the map a dashed line to its order, a dotted line to its goal and a square at its home. The player's card adds ranks, contracts, the run's ledger and XP by source. The Economy tab of the side column swaps your truck's panel and the truck card for the economy and asks the worker for a snapshot, which the worker sends again every game hour. The page keeps its place and scroll when a snapshot arrives. Its overview opens on a count of empty and short goods and stopped lines, then a grid with one column per town and one row per good. Each grid cell is the stock, or with the Price lens the buying price, beside a small trend line of the run so far, on a red fill when the good is empty and a dim red fill when it is short. Under the grid, the list of what is short has one row per empty or short good, the hours it has been so, a trend line and one sentence on why: the line that makes it is stopped and what it lacks, the makers are out too, haulers lost a shipment on the road, trucks are on the way, nobody hauls it, or what drained it most in the last game day. The list shows the worst few rows, empty goods first, then stopped lines, then short goods by how far below target, and folds the rest under a count. Below it come the best trade for each good, judged by `tradeOutlook()` in `src/sim/npc-decisions.ts` as the live trader with the most cargo room would judge it: the net gain for a load after fuel and road risk, the fuel cost and the distance, with a mark and the reason when traders skip it. Then comes the road news. A click on a good opens its page: each town that trades it as maker, user or trader with stock and price trends, the trucks carrying it now, which a click opens on the Trucks tab, and its price gap. A click on a town head, a grid cell or a town on the map opens that town: its production lines with their run state and missing inputs, its goods with stock and price trends and the reason for each shortage, and the last game day's stock changes by cause. A trend line draws the stock as a solid line, the stock target dashed, the short zone as a light red band, a site surge or breakdown as a green or amber band and a lost shipment as a red tick. The map rings every town that has a short or empty good with the count of them. A good page draws its production links with an arrow from maker to user, and a town page draws the links of that town. Production links and shipments follow the roads, with each town pair's road route found once and kept, and draw over a dark halo. A shipment is a dashed line in the color of the good from the truck, along the road, to its destination, and the ones that do not match the open page fade. The Trucks tab brings the card back, and a click on a truck marker returns to it. A stall shows in red, and a thrown turn stops the run and shows its stack. `SimRun` in `src/sim/progression/sim-mode.ts` holds the run and the card and log formats. The map draws each truck as a baked sprite: `npm run sim:sprites [-- --cpu]` renders every chassis in every paint the game gives it, from the game camera 35 degrees above the ground and at 16 headings, through the dev-only `sim-sprites.html`. It writes one webp sheet per chassis and paint to `public/sim-sprites/` and `manifest.json` with each sprite's cells, anchors and size. The page loads them at start and adds the colored shadow, so it never renders. A marker whose chassis and paint have no sprite stops the page and names this command. Run it after a change to a chassis model, a palette, a template paint or the chassis a template rolls. A test fails when a sprite is missing or stale.
- `npm run escort:report [-- <dir>]` reads `escort-<seed>.run.jsonl` and `sprinter-<seed>.run.jsonl` from `tmp/progression/` or the given directory. It prints, per stretch and seed, the hauler damage and condition, the player's shots, the fights, the enemy count and the useful outpost parts against the money in hand. It then prints the play check and the balance checks. [Bots](architecture/bots.md#reading-a-run) lists them.

A recorder run writes these files beside the trace.

- `<bot>-<seed>.turns.jsonl` has one line per turn: the player truck's position, money, net worth, fuel, parts, goods, contracts, order, flags, the hostiles in sight with the player's odds against each, the money moved by kind and every event that touches the player.
- `<bot>-<seed>.world.jsonl` has every event of every turn, each NPC's money moved by kind and a snapshot of every truck every 10 turns. A 5-day run writes about 7 MB.
- `<bot>-<seed>.stream.jsonl` is the run stream of the bot's view, in the format of the run log the Save panel exports. It is much smaller than `world.jsonl`. The Run log section of [Saves](architecture/saves.md) describes the lines. `progression:analyze` does not read it.
- `<bot>-<seed>.run.jsonl` is written by a Chaos Highway run and holds the stretch statistics that `escort:report` reads.

`npm run run:timeline -- <log.jsonl> [--by day|stretch]` reads a run stream from the recorder or from the Save panel's export and prints the story per day or per stretch. A stretch ends at each `roadOpened` event. It drops the records a load rewound past and skips records from a build before the run stream. Each section lists the trucks that came into view, the fights, the player orders, changes in parts, goods and money, wrecks and knockouts, and the spans where a player truck stayed within 2 tiles for 20 turns or more. The constants `STALL_TURNS`, `STALL_RADIUS` and `FIGHT_GAP_TURNS` are in `src/sim/progression/run-timeline.ts`.

An A/B test checks a balance change before it goes into `src/data/`.

- Write a patch module that imports a data file and changes a number in place, such as `DISTANCE_PREMIUM.perTile *= 2`.
- Record the same bots, seeds and turns twice, once plain into one `--out` directory and once with `--patch <file>` into another.
- Run `progression:report` on both directories.
- A number a data file derives from another at load time does not follow the patch, so patch it as well. The report says so when both sides end on the same net worth.

## Other simulation harnesses

- `npm run search:effort -- --seed 1 --turns 1500 [--post-until 1200] [--out tmp/search-effort]` measures search jobs faster than the recorder, since they post rarely. It plays the searcher, and whenever the bot stands at a board with no search, holds none and the turn is before `--post-until`, it posts a search there by the real candidate rule, `searchCandidates()` and `rollContract()`. It writes `searcher-<seed>.json` every 25 turns, so a stopped run keeps its numbers: the posts, the search effort and the `rewardTurns` the reward formula in [the economy mechanics](wiki/mechanics/economy.md) gives.
- `npx vite-node scripts/sunward-pacing.mjs -- --seeds 1,2,3` plays one Sunward night per seed with every truck on far travel, as the recorder plays, and on into the morning, and starts at the column's ride-out, prints when the Cavalcade holds its posts, when the first car leaves one and when every car is home against the next ride-out, the other drivers in the crater zone per turn by day and by night, stalls and hunts per week. `--quiet` keeps only the order and the player and stops every other spawn, so a seed takes about a minute and measures the undisturbed ride. Its closing line gives the slowest last arrival after ride-out over the seeds in which no car broke down or fought on the way and the lead that needs, which sets `SUNWARD.rideLeadTurns` after a Hollow, pad or route change. `npx vite-node scripts/hollow-site.mjs` searches the baked map for a place for the Hollow fort: it lays the fort's real pieces, the laager and the pad at each candidate, rejects any that touch a map prop, site or deck, sit on more relief than `MAX_RELIEF` or hide the pad or the gate from the fixed camera, and prints the candidates that pass with a route from the gate to a vigil post, shortest drive first. `MIN_ROAD_GAP` defaults to a maxed driver's day sight plus `SUNWARD.sightMargin` plus 10 tiles from the nearest piece or the pad, `MIN_SITE_GAP` to the gray vision radius from the nearest piece or the pad, `DRIVE_MAX` to 280 and `PICK` to the number of candidates it routes, nearest the crater first. `MIN_CRATER_GAP`, `MIN_ROAD_GAP`, `MIN_SITE_GAP`, `DRIVE_MIN`, `DRIVE_MAX` and `POST_RING` set the limits, and `VERBOSE=1` prints every route it tries.
- `npm run combat -- --a merc,merc:snowball --b buggy,buggy:buggy@heavy,buggy+buggy --seeds 1-5` plays fights between two sides on flat open ground through the real turn pipeline and physics. Every lineup of `--a` fights every lineup of `--b`. `+` joins trucks in one lineup. A truck is `driver:gear`.
- The driver is an NPC template, whose brain drives the truck.
- The gear is a start kit, an NPC template's rolled loadout as `buggy` or `buggy@heavy`, or `mg/plates+ram` for one gun and one armor on a hauler. `mg*3/bare@wagon` mounts three guns on a chassis other than the hauler. `bare` means no armor. A driver without gear takes its own template's loadout.
- A scripted driver, `stand`, `orbit`, `charge` or `kite`, steers the player truck alone on side a. It tests one way of driving.
- `--arena <tiles>` rings the fight with rocks that many tiles out, 10 at most so the ring fits in sight. The arena resumes hostility after a truce or surrender, so survivors fight until a knockout or the turn limit. An arena allows 400 turns by default, open ground 40. `--turns` overrides it.
- `--map chaos-highway[:<seed>]` fights on window 0 of the Chaos Highway of that seed with its rules, the sides lined up along the road just short of a scene. The report adds `across`, the farthest any fighting truck got from the centerline. A Chaos Highway truck is a scripted driver with the kit, as `orbit:chaosHighway`. `--map` and `--arena` do not mix.
- `--crew a|b` joins that side's trucks into a raider crew led by its first truck. Only the leader starts with a feud, so the members join by their own crew call.
- `--guard` makes the merc that rides beside a scripted player on side a, as `stand+merc`, the player's hired guard. It starts with no feud.
- `--late b:20` holds side b's last truck out until turn 20, then brings it in. `--bystander trader` parks a neutral truck of that template at the edge.
- The report adds, per side, the trucks still in the fight, knocked out and fled at the end, and what became of the bystander: calm, fought or out.
- Rams landed shows, per side, how many damaging crashes on a side with a ram or spikes put the hit on them.
- `--gap <tiles>` sets the starting distance and `--orbit <tiles>` the scripted orbit radius. The defaults are 8 and 6.
- `--set RULES.leadError=3` changes one balance number for the run, so a tuning idea is measured before any code changes. It may repeat.
- `--trace` prints every turn. `--out <dir>` sets the output, `tmp/combat/` by default. It writes `fights.json` and `report.md` with outcomes, hit rates and damage per pair of lineups, and names the side that fled.
- `npm run economy:shock -- --seeds 1 --days 1 --shock none,robSorgut,massacre,pumpSurge,stockpile --at 120` plays a Roaming world with the player parked and every truck on the far rules, and applies a shock through sim rules at turn `--at`: `robSorgut` robs every sorgut shipment in flight, `massacre` wrecks every trader and convoy, `pumpSurge` starts a Pump Station surge and `stockpile` has the player buy out the Granary's rations. Each shock and seed runs in its own process. It writes `tmp/economy/<shock>-<seed>.json`, a `.partial` file at each quarter day, and `tmp/economy/report.md`: traders and convoys alive, fuel rationing hours per site, every stock flow per day by cause, each site's stock by quarter day against its target, how long each essential good takes to come back within 20% of target, and the best routes by margin per 20 crates after fuel. One far day takes about 20 minutes on a loaded machine, so keep runs short and in the background.
- `npm run traffic -- --seeds 1-3 --turns 300 --layer physics|far` plays a world of NPCs with the player parked and measures how fast trucks drive on the road, in km/h of the path driven each turn. The `physics` layer drives every NPC in Rapier and the `far` layer uses far travel only. It reports steady cruise per class and per chassis, the causes of slow healthy samples, the low-fuel share, resupply starts, the most NPCs dry at once and collisions. It writes `tmp/traffic/<layer>-seed-<n>.json` and `tmp/traffic/<layer>.md`.
- `npm run income -- --seeds 1-6 --days 2 --policy robber,convoyRobber,trader,scavenger --jobs 3 --candidate A` plays each policy on the `midgame` start kit, every skill at rank 2 and no gear bought, with every truck on far travel, one process per seed and policy. Each run writes `tmp/income/<candidate>/<seed>-<policy>.json`. `--out` sets the folder. The file records the candidate name and the build, which is the last commit that changed non-test code in `src/` plus a hash of any uncommitted change there. A run whose file exists for the same build is skipped. A file for another build fails the batch. The batch writes `report.md` in the folder with net worth per in-game hour, daily percentiles, robbery attempts by target and answer, and wallets by day. It throws when a run's money ledger does not match its money change. Run it in the background.
- `npm run income -- --report tmp/income/A --baseline tmp/income/baseline` writes only the report: the gate report of issue 157 with gates G1 to G7, and the run tables. The thresholds are constants in `src/sim/progression/income-report.ts`. A gate fails loud on runs of mixed builds.
- `npm run loadouts -- --rolls 60 [--template merc] [--level heavy]` rolls NPC loadouts per template and prints the gear level mix, mean guns, armor cover, speed kept and gear money spent. It writes `tmp/loadouts.md`.

## Generated files

- `npm run models:bake [-- <name> ...]` bakes the crease shadow mask of every truck model in `SURFACE_MODELS`, or of the named ones, into its `.glb` in place, through `tools/blender/bake_mask.py`. Run it after rebuilding a truck model, then run `npm run icons`. Logs go to `tmp/models-bake/`.
- `npm run icons [-- --cpu] [--plans]` renders every part, good and chassis icon from the game's models through the dev-only `icons.html`. It writes the sprite sheets in `public/icons/`, `tint.svg` and `plans.svg` in `src/ui/`, the manifest `src/data/item-icons.json`, and the labeled atlases and the closest-pairs report in `public/icons/atlas/`. It fails when a weapon barrel does not read from lower left to upper right in the diagonal view, and prints each failing entry first. `--cpu` draws in software and takes under a minute. `--plans` writes only `plans.svg`, with the top view and the outline of every chassis. [Art pipeline](art.md#icons) has the rules.
- `npm run survey:pictures [-- --cpu]` renders the journal picture of every survey site from the game's ground, props, outlines, daylight and camera direction through the dev-only `survey-pictures.html`. It writes `public/survey/<site id>.webp`, the manifest `src/data/survey-pictures.json` and a labeled contact sheet in `tmp/survey-pictures/sheet.png`. Run it after `npm run old-spots`. A test fails when a picture is missing or stale.
- `npm run map:bake` builds the map from `MAPGEN.seed` in `src/data/terrain.ts` and writes `public/maps/icarus.bin`, a whole-map picture and close-ups in `tmp/map/`. A save made on another map does not load. Boot offers to carry the player over, as [Saves](architecture/saves.md) describes, so a new map file needs no major save bump. Run `npm run old-spots` after it.
- `npm run old-spots` writes the old-world loot spot picks of the committed map to `src/data/old-spots.json`, the off-road survey sites for survey contracts to `src/data/survey-sites.json`, and the fair claim clues of every claim wreck and shop to `src/data/claim-clues.json`. Run it after a map rebake or a change to `OLD_PLACES`. A test fails when the file is stale.
- `npm run save:shape` records the saved shape of the current save format and the saved quest names in `src/three/save-shape.json`.
- `npm run wiki` regenerates the tables in `docs/wiki/` from the code. A test fails when a table is stale or wiki prose names a data path or source file that no longer exists.
- `npm run quest-art -- <source image> <key>` runs the quest picture post-process, writes `public/quest-art/<key>.webp` and then its crop sheet. It needs `uv`. `npm run quest-art:crops -- [key ...]` writes only the crop sheets `tmp/quest-art/<key>.png` for the keys in `src/data/quest-art.json`, or all of them, and needs only Pillow. [Quest art](art/quest-art.md) has the style prompt.
- `npm run quests:build`, `npm run quests:check` and `npm run quest -- <quest>` build, check and play the ink quests. `npm run quest:view -- <quest>` opens the game at a quest scene. [Quests](architecture/quests.md#tools) has the flags.

## Sound and publishing

- `npm run sfx:board` opens the dev sound board for auditioning every cue.
- `npm run blocks:sim -- --song <name> <event@seconds ...> [--seed 1] [--length s] [--end s]` plays a scripted fight through the combat music's real session on a simulated clock and prints the blocks it chose, the lanes, the events that opened them and a summary. `--help` lists the events. [Sound](sound.md) has the rest.
- `npm run score:song -- <plan.json> <takes>` generates a combat song from a bar-exact section plan with the ElevenLabs music API. It costs credits.
- `npm run sfx:import -- <cue> <file...>` imports files as variants of a cue in `src/data/sounds.ts`.
- `npm run sfx:gen -- <cue> <count>` generates variants with ElevenLabs. It costs credits and fails when `count` exceeds `SFX_MAX_GENERATIONS`.
- `npm run sfx:reimport` rebuilds every sound file from the raw source path stored in its tags, after an import change.
- `npm run sfx:reloop -- <cue or file>...` remakes the shipped files of free sfx loops as steady loops in place, at the same average loudness, for loops whose raw source is gone. A file name remakes that file only. It does not run the import's tone steps again, and it stops when its output fails the loop check.
- `npm run itch` builds the last commit in a clean worktree, uploads it to itch.io with butler and names the upload after the commit. [Publishing](publishing.md) has the one-time setup.

## Config

`src/config.ts` holds the world seed, start kit, combat playback times, save interval, Space hold delay and travel speed multiplier. The world seed drives sim randomness, like where the first NPCs start, but not the map. A null seed rolls a new one for each new game, and the save keeps it.

`.env` holds `ELEVENLABS_API_KEY` and `SFX_MAX_GENERATIONS` for sound generation, and `ITCH_TARGET` and `BUTLER_API_KEY` for publishing. `.env.example` lists them.

## Browser scripts

A browser script is for what the screen shows: UI, rendering and screenshots. Playtest game behavior with the progression recorder instead. A still image of a model, part, truck or prop comes from `npm run shot`, never from a script of your own.

- Write the Playwright script in `tmp/`.
- Launch Chromium with `gpuArgs()` from `scripts/gpu.mjs`. SwiftShader renders on the CPU at 10 to 20 fps, so its frame rate says nothing about the game.
- Open the game with `playUrl()` from `scripts/game-url.mjs`. It adds `?play`, which in dev skips the start menu and loads the newest save or starts a new game without the intro. A production build ignores `?play`, so `boot:time` writes a boot request into session storage instead.
- In dev, `?seed=<n>` gives a new game a fixed seed. `?lang=pseudo` shows English padded by 40% to find layouts that break on longer text. `?lang=ru` and `?lang=en` open that language for the visit without storing it. `?ui-size=80`, `90`, `100`, `115` or `130` opens that UI size for the visit without storing it. The window still limits it to a size the UI layer can hold.
- In dev the game is on `window.__ROAM__`. Its world is `__ROAM__.state`, and `__ROAM__.language.set('ru')` switches the language. To set up a situation, clone that world, edit it and pass it to `apply()`.
- `debugScreenOf(x, y)` gives the screen point of a map point on the ground, for clicks.
- The camera has a fixed bearing. To shoot a face it does not show, wrap the instance's `tick` on `__ROAM__.rig`. Call the original, then move `rig.camera.position` around `rig.center` to the bearing and elevation wanted at the same distance, and `lookAt(rig.center)`. Keep this in the script and out of game code.
- `node scripts/sound-decode-check.mjs <url>` runs `sound-check.html` through a caching proxy in Playwright Chromium, Firefox and WebKit: every sound decodes, a cached truncated `hit-metal-2.ogg` is replaced by the real buffer, and an injected decoder fault is recovered after boot.

## Phones

`npm run mobile` is emulation. Chromium treats touch as a fast fake of a phone: it has no notch, no browser bars, no pull-to-refresh and no edge-swipe back. A real device must run this checklist on Android Chrome and on iOS Safari, and report the device, OS, browser, viewport, the result of each line and any flow that does not work. The checklist is the eleven steps of the check, plus the browser gestures:

1. Open the game, tap Options and pick 80% and 130% UI size. A size the screen cannot hold is off and shows its reason. Pick one that fits, then tap New game and Start.
2. Drag the map with one finger: the view moves and follow turns off. Tap Center on truck. Pinch to zoom.
3. Tap the ground: a route is set. Hold the ground: a stop point is set.
4. Tap End turn.
5. With a gun picked in the Guns drawer, tap a truck: its card opens and nothing aims. Tap it again: the gun aims. Tap the card's × to let go.
6. Tap a town: a stop is set at its pad. Park there, tap the action button, buy one item, close the town.
7. Open the inventory from the Truck drawer. Hold an item, then drag it into storage. Select it there, tap a grid cell, tap Rotate and tap the preview: it lands turned, with one finger.
8. Open each drawer, Menu, Help and Options, and close them.
9. Hold a disabled control: its reason shows.
10. Save through Menu, reload the page and tap Continue: the turn and the position are the same.
11. Open Driver and reach every perk and Buy button. With a gun picked, tap a truck twice, then tap a part on its card: the gun aims there.

Browser gestures to try on top of that: pull down from the top of the screen on the map (the page must not reload), swipe in from the screen edge (the game must not leave), double-tap a button (the page must not zoom), pinch outside the map (the page may zoom), turn the phone mid-turn, and on a phone with a notch check that no control sits under it.

## Debugging

- In dev, any uncaught error shows a fullscreen crash screen. Outside dev, errors after boot go to the browser log and the debug console, and the game keeps running. Boot errors always show the crash screen. A browser without WebGL 2 gets a notice that names the fixes, and the error reporter does not send it. A boot download or sound fetch that gets no data for 20 seconds counts as dropped and is retried, and a slow download that keeps getting data is never cut.
- Every game file loads through `fetchAsset` in `src/fetch-asset.ts`, which retries a dropped request or an HTTP 408, 429, 500, 502, 503 or 504 three times, waiting 1, 3 and 9 seconds between tries. When a file still does not arrive, the boot screen shows Try again and the error reporter does not send it. A missing file (404) still shows the crash screen and is reported, except a map prop model, which gets a grey box stand-in and a report.
- The crash screen lists the error, its source file, line and stack when known, the game version, the boot step, the browser and the page address without its query. It shows no save content.
- A hidden "Script error." with no error object, from a script outside the game such as a browser extension, never crashes and never holds saves. It goes to the browser log and once to the debug console.
- A failed turn does not play. The log shows it, automatic turns stop, and no save is written until a turn completes without an error.
- The factory's release, dev and candidate builds also send every error to the factory's error endpoint, set by `ERROR_REPORT_URL` at build time. A build without the URL sends nothing. `src/three/error-report.ts` sends each distinct error once per session, with the game context and, for a failed turn, the physics drive the turn started from.
- The game context is the same in error reports and in the report form: the version, the browser, the language, the screen size, the turn, the log, the world in memory and the Autosave. `GameContext` in `src/three/error-report.ts` builds it. It holds the Autosave from the moment the saves open, and a world that cannot be written into the report goes as `world: null` with an empty log, reaches `noteError()` and never stops the send. Neither report writes a save slot. `factory/src/error-reports/report.ts` checks the same shape, so change both together. The report form takes the world when the player presses send, so the report holds the game as the player saw it. The form is reachable from every screen the game code shows: the HUD corner in play, the Menu entry over every modal screen, scenes the player cannot close included, and the report desk (`#report`) above the boot screen, the start menu, the save rescue, the defeat screen, the crash screen and its notices. `npm run boot:check` opens it on each. The form says a report is sent, failed or over the factory's hourly cap. Where no HUD toast exists, as on the desk, it says sent on its own status line. A 429 shows the minutes until the cap resets from the answer's `retryAfterSeconds`, so the player waits instead of retrying.
- `npm run error:replay -- <report.json.gz> [--from autosave]` loads the world of an error report or a player report headless, runs its turn and prints what it throws. Run it on the report's commit. `--from autosave` starts from the report's Autosave. Only a failed turn's error report reruns exactly, since only it holds the physics drive.
- The backquote or § key opens the debug console in every build. Type `help` for its cheat commands. `src/ui/console.ts` parses the commands and calls one pure function per cheat in `src/sim/cheats.ts`. `tp <id>` takes any named place of a Roaming world, the Sunward Hollow included, from `worldPlaces` in `src/sim/sites.ts`, and refuses on Chaos Highway, where `tp <x> <y>` still works. Bad input throws `CheatError`, which the console prints. Any other error reaches the crash screen. God mode is a saved player flag. It restores the truck in `endTurn` before the destruction and defeat checks. `sunward dusk` fills the Sunward Hollow and skips to the column's next ride-out, `sunward hunt` sends tonight's hunters out and `sunward roster` prints the night ledger.
- The console command `seeall` toggles a see-all view for the session: the market tab shows each site's recipes with their surge and breakdown tags, where a good is made and used, and the slow import tag, the log tells site surges and breakdowns, and the hover card shows every NPC's traits and cargo as the `readDriver` and `cargoEye` perks would. It grants no perk action. `src/ui/see-all.ts` keeps the flag, outside the world, so a reload turns it off.
- `src/perf.ts` holds named timers for seams, never hot loops, and merges the measurements of the turn worker and the preview worker. The console command `fps` shows them in a panel in the top left.
