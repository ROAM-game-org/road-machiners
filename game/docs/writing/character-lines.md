# Character lines

Every line a named character says is generated by another model speaking as that character, one call per line. The agent then edits the result and puts it in the quest. Models imitate voices well, and a separate call per line keeps each person from sounding like the writer of the scene.

## When to use it

Use it for every spoken line of a named person, in quests, talk hubs and page scenes. Narration, choices, notes and UI text stay with the agent. A minor speaker with one job can skip it.

## The call

English goes to codex and Russian goes to agy. Claude never writes a character line or any Russian text.

- English: pipe the prompt to `codex exec -s read-only --skip-git-repo-check --ephemeral -o <out file> -`.
- Russian: `agy --dangerously-skip-permissions -p "<prompt>"`. [Russian copy](russian.md) has the model flags.
- Check the exit code of every call. A failed call writes nothing, and agy can hit a quota that lasts days. Report the lines that are missing, and never fill them in by hand.
- A reply of more than one sentence is built one sentence at a time. Each call asks for one sentence on one small topic, and its Context ends with "She has said so far:" and the sentences already chosen. Pick the best take of each sentence before you ask for the next. A call that is asked for a whole speech gives a long, rambling monologue with invented details.
- Build each line three times over, as three whole chains of sentences, and pick the best chain per line. Mixing the best sentences from different chains is fine when they do not repeat each other.
- Independent lines can run in parallel. Keep scratch prompts and outputs in `tmp/`.

## The prompt

One shape, always:

```
<one line about the game>

Write a piece of dialogue from the character's POV for our game.
Character: name, key aspects, how they speak, a small sample of speech
Context: short facts this character knows right now
What to speak about: brief raw description of what they should say
Reply:
```

Fill each part like this.

- Game line: one short sentence on what the game is, the same for every call, like "ROAM is a post-apocalyptic RPG where you drive an armed truck". It never says how people talk, what tone to use or what the economy is. Style belongs to the character part only, because any style words here reach every character and make them sound alike.
- Character: copy the person's sheet from [Voices](../lore/voices.md), and the aspects from [Characters](../lore/characters.md) when they have an entry. Add one or two sample lines taken from the person's sheet, never ones you wrote. For Russian, say to reply in Russian and paste the names from the glossary in [Russian copy](russian.md).
- Context: only what the character knows at this moment. When the character answers the player, put the player's question in Context word for word, as the player saw it. No plot, no other branches, no game words.
- What to speak about: the topic in one plain sentence, like "Greet the driver and introduce herself. Introduce them to Bowl." Never put phrases, jokes, images or the old line in it, because every word you give is a word the character did not choose. Give a fact only when the line must carry it, and state the fact flat. Do not ask for a length.

## Keep voices apart

- A sample teaches by repetition. If every sample has the same joke or the same pet word, every line will carry it. Use samples that show the speech rule in different ways.
- Do not tell the model to always do a habit. Say a habit happens sometimes, or the model will do it in every line.
- Name a topic or trade once at most, as the job, like "keeps the well house". A theme from the sheet such as money, prices or water, repeated in the aspects and again in a sample, comes back in every line. Leave themes out of the prompt and let the facts of the scene bring them in.
- Take several takes of a line and pick the best. Cut invented details in the edit, instead of adding rules about them to the prompt.
- Read the first batch for tics before you use any of it. Count how many lines share a joke, a pet word or a sentence shape. If more than a few do, change the prompt and run the batch again.

## Edit the result

The model gives raw material. Before it goes in the quest:

- Check every fact against the lore and the facts you gave. Cut anything the model invented. Put every practice, cause and detail through the [sense check](../lore/README.md#sense-check).
- Cut the length to what the scene needs.
- Split every semicolon or dash a model left in into two sentences. The voice test rejects them.
- Cut a tic that repeats from the line before, even if the model liked it.
- Remove words that agree with the gender of the player, and any count of years.
- Read the line against the [Humanizer](humanizer.md#how-roam-uses-it) the way its How ROAM uses it section says for fiction. Never put the Humanizer in the call itself, since style words there reach every character.
- Keep the voice. Fix rhythm and wording only. Do not smooth it into your own style.
- Read the line with the name hidden. If another sheet could own it, run the call again with a sharper character part.

Then check against [Writing dialogue](dialogue.md) and the rules in [Writing quests](quests.md).
